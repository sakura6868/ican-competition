## 1. 本轮目标

把当前“多个模块已经存在，但主要靠命令、预生成报告和人工刷新串起来”的原型，完善为用户可以直接在网页内完成的产品：

1. 教师上传一段标准教学视频，可自动生成结构化 SOP。
2. 教师可以在网页中修改步骤、工具、对象、动作、顺序和分值，再发布 SOP。
3. 学员上传自己的操作视频，系统自动分析、显示进度并生成步骤级评分报告。
4. 报告中的每一个通过、失败或证据不足结论，都能定位到视频时间和证据画面。
5. 同一视频的已完成分析可以缓存重放，答辩现场即使外部模型不稳定也能完整演示。
6. 系统明确区分“正式预录考评”“实时训练辅助”“离线人工复核”，避免三个模式混在一起。

本轮完成后，项目应达到：

> 可由教师和学员在 UI 中独立跑通“知识导入 -> SOP 生成与发布 -> 学员视频考评 -> 证据报告 -> 改进建议”的比赛演示级闭环。

- 大规模自训练视觉模型和生产级准确率认证。
- 多工位、多摄像头、多租户和企业管理后台。
- 阶段 12 的打包发布工作。

开发期间只使用当前已有的公开授权样本、演示数据和安全录制视频。上述事项保留 TODO，不要删除已有安全代码，也不要为了开发方便降低现有加密、认证和权限能力。

“证据不足时无法判断”属于评分正确性，不属于本轮暂缓的合规门禁，必须实现。

## 3. 产品主线与角色

### 3.1 教师流程

1. 登录教师账号。
2. 在“知识库”上传标准视频，可选上传手册。
3. 选择工序模板或创建新工序名称。
4. 点击“生成 SOP”，网页显示抽帧、视觉分析、步骤编译和校验进度。
5. 进入 SOP 编辑器，逐步调整名称、工具、对象、动作、前置步骤、关键步骤和权重。
6. 点击“发布”，SOP 出现在考评中心的可选列表。
7. 在考评中心查看学员提交记录、得分、步骤结果和证据。

### 3.2 学员流程

1. 登录学员账号。
2. 选择教师发布的 SOP。
3. 查看步骤目标和拍摄建议。
4. 上传预录操作视频，或从浏览器录制完成后提交。
5. 系统自动创建考评会话、处理视频和展示进度。
6. 完成后自动进入报告，不要求反复点击“查看评分”。
7. 查看总结果、步骤状态、证据画面、时间轴和改进建议。

### 3.3 管理员流程

本轮只保留已有账号创建、角色分配、停用和密码重置能力，不扩展复杂组织管理。

### 3.4 实时训练流程

“实时考评”改名为“实时训练辅助”或在页面中明确标记 Beta：

- 本地模型显示手部、人体和画面质量等即时反馈。
- 外部 Qwen 只做每 4 至 6 秒一次的低频语义检查。
- 页面提示当前建议步骤和识别到的工具/动作。
- 最终正式成绩仍由录制完成后的预录分析产生。
- 本轮不承诺外部大模型达到实时帧率。

## 4. 总体技术路线

### 4.1 标准视频生成 SOP

```text
上传标准视频/手册
  -> 创建处理任务
  -> 视频探测与统一转码
  -> 全片均匀采样 + 场景变化补帧
  -> 带真实时间戳的关键帧序列
  -> Qwen 多帧批量分析
  -> 工具/对象/动作/阶段候选
  -> 结构化 SOP 编译
  -> 可编辑草稿
  -> 教师发布
```

### 4.2 学员视频自动考评

```text
选择已发布 SOP + 上传学员视频
  -> 创建考评会话
  -> 抽取带真实时间戳的关键帧
  -> 根据 SOP 词表执行多帧视觉分析
  -> 生成时间有序的动作事件
  -> 时间平滑和重复事件合并
  -> SOP 步骤对齐
  -> 确定性评分
  -> 证据时间轴与改进建议
```

### 4.3 模型职责

- Qwen 多模态 API：识别画面中的工具、对象、动作和阶段语义。
- MediaPipe Hand：本地手部存在、手部位置和基础质量反馈。
- YOLO COCO：只作为通用人物/常见对象辅助，不再宣称能识别工序专用工具。
- 状态机和步骤对齐器：决定动作事件与 SOP 步骤的对应关系。
- 评分引擎：唯一数值评分来源。
- 大模型反馈：根据已经确定的步骤结果生成自然语言建议，不允许直接修改分数。

本轮不训练新的大型视觉模型。先把 Qwen 主链和可复现缓存做完整；工序专用本地模型放到主体闭环完成之后。

## 5. 阶段一：修复预录分析基础

### 5.1 统一关键帧与真实时间戳

修改 `backend/gongxu/media/video.py`：

- 新增 `SampledFrame` 数据结构：`path`、`frame_index`、`timestamp_ms`、`source_pts`。
- `extract_keyframes_uniform` 返回 `list[SampledFrame]`，不再只返回路径。
- 时间戳基于视频时长或 FFmpeg PTS，必须覆盖视频开头、过程和结尾。
- 同时支持均匀帧和场景变化帧，合并后按时间排序并去重。
- 默认第一遍最多 32 帧；视频少于 15 秒时降低采样数量。

修改 `backend/gongxu/vision/pipeline.py` 和 `backend/gongxu/vision/demo.py`：

- 在切分 batch 之前生成全局 `(image_bytes, timestamp_ms)` 列表。
- batch 内不得重新从 0 编号。
- 合并检测结果后按 `timestamp_ms` 排序。
- 预录流水线与 CLI demo 必须使用同一套采样函数。

验收：

- 24 帧分成 6 个 batch 后时间戳仍严格递增。
- 60 秒视频首帧接近 0 秒，末帧接近 60 秒。
- 步骤证据点击后能定位到原视频正确位置。

### 5.2 改造 Qwen 多帧输出结构

修改 `backend/gongxu/vision/adapters_qwen.py`：

- 输出从单纯 `Detection` 扩展为受控事件：
  - `frame_index`
  - `hand`
  - `tool`
  - `object`
  - `action`
  - `phase`
  - `confidence`
  - `evidence_reason`
- prompt 中包含当前 SOP 的完整步骤摘要，而不只包含孤立词表。
- 要求模型判断“这一帧最可能对应哪个步骤”，但该判断只作候选，最终仍由本地对齐器决定。
- 批处理失败时允许逐帧降级；每个任务设置最大调用次数和可见进度。
- JSON 解析允许单个错误 item 被跳过，不能因为一项格式错误丢失整个 batch。

### 5.3 两遍式采样

第一遍：

- 全片均匀采样 24 至 32 帧。
- 识别大致操作阶段、空闲片段和动作变化位置。

第二遍：

- 在候选步骤切换点前后各补 1 至 2 帧。
- 总帧数上限 48，避免费用和等待时间失控。
- 对明显无人的长空闲片段不补帧。

第二遍作为可配置增强项；若外部模型失败，保留第一遍结果继续给出“证据不足”，不能让整个任务永久停在处理中。

前端提交后自动轮询任务；完成时直接打开生成的 SOP 草稿。

- Qwen 根据标准视频生成候选词条，教师可在 SOP 编辑器中接受、改名或删除。
- 新词表保存在数据库或 SOP 版本中，不要求改 Python 文件才能增加工序。
- 未找到词表时返回“请先创建工序词表”，不能静默回退到角磨机词表。

## 7. 阶段三：学员视频考评闭环

### 7.1 合并“上传”和“创建会话”操作

完善 `AssessmentView.vue`：

- 提供清晰的三步向导：选择 SOP -> 选择/上传视频 -> 开始分析。
- 用户新上传视频后，自动完成资产登记、视频处理和会话创建。
- 不要求用户先去知识库上传，再回考评中心手动选择。
- 已有资产仍可从下拉列表复用。
- 显示视频文件名、时长、分辨率和缩略图。

### 7.2 自动任务进度和恢复

- 点击开始后自动创建 `recorded_assessment` job。
- 页面显示当前阶段、百分比、已分析帧数、预计剩余时间和失败原因。
- 页面刷新后根据 session/job id 恢复进度。
- worker 结束后页面自动加载报告，不再要求用户手动点“查看评分”。
- 任务失败提供“重试”按钮，重复提交不创建多份冲突报告。

### 7.3 事件合并与步骤对齐

完善 `backend/gongxu/vision/facts.py` 和 `align.py`：

- 相邻帧中相同 `tool/object/action` 合并为一个时间区间事件。
- 允许短时漏检，不要求每秒都存在完全相同检测。
- 步骤匹配综合：动作、对象、工具、候选步骤、前置关系和时间顺序。
- 工具或对象不清楚时可以用动作和步骤上下文匹配，但降低 confidence。
- 明确看到错误工具、错误动作或越过关键步骤才判 `failed`。
- 没看清、遮挡或没有足够连续证据判 `insufficient_evidence`。
- 每个步骤保存主要证据帧、时间范围和简短判断理由。

### 7.4 评分规则

保留六维度分数，但修改最终结果语义：

- `passed` 步骤计入已完成权重。
- `failed` 步骤按明确错误扣分。
- `insufficient_evidence` 不冒充失败，但降低证据覆盖率。
- 任一关键步骤证据不足，最终结果为 `inconclusive`。
- 总证据覆盖率低于 80%，最终结果为 `inconclusive`。
- `inconclusive` 可以展示“临时分数”，但 UI 不显示绿色“通过”。
- 关键步骤明确失败时总分最高 59，结果为 `fail`。
- 其他情况下总分不低于 60 为 `pass`。

评分阈值应集中放在 scoring profile 中，不散落在 UI、demo 和测试脚本里。

## 9. 阶段五：实时训练辅助

### 9.1 页面定位调整

修改导航和 `LiveView.vue`：

- 页面名称改为“实时训练”。
- 明确区分“即时画面反馈”和“低频语义识别”。
- 不显示虚假的高 FPS 语义推理指标。
- 页面结束后自动把录制视频提交到预录考评，生成正式报告。

### 9.2 帧处理策略

- 浏览器预览维持 10 至 15 FPS。
- 本地手部/人物质量检测按设备性能运行。
- Qwen 只保留最新一帧，每 4 至 6 秒最多提交一次。
- 新帧到达时丢弃过期待处理帧，不能在 WebSocket 队列中累积。
- 外部推理放到线程池或后台任务，不阻塞 FastAPI 事件循环。
- 页面显示“正在分析最近画面”，不把 5 秒延迟包装成实时识别。

### 9.3 实时反馈内容

- 当前建议步骤。
- 最近识别到的工具、对象和动作。
- 画面是否过暗、无人、手部不可见或遮挡明显。
- “继续”“可能漏步”“工具可能不匹配”等辅助提示。
- 实时提示不直接生成最终考试分数。

## 10. 阶段六：可复现演示模式

### 10.1 三个预置样本

提供一键加载的三类演示：

- 完整操作样本：主要步骤可识别并获得通过或接近通过结果。
- 明确错误样本：至少包含漏关键步、错序或错工具中的一种。
- 视角不足样本：返回无法判断，展示可信拒判能力。

预置结果必须来自一次真实运行归档，不允许手写最终分数。保存模型返回的结构化事件和评分输入，答辩时可使用 Replay 方式复现。

### 10.2 演示模式入口

在工作台增加“答辩演示”入口：

1. 标准视频生成 SOP。
2. 完整样本自动考评。
3. 错误样本对比。
4. 点击失败步骤跳转证据。
5. 展示跨视角或证据不足拒判。

在线模式允许重新调用 Qwen；离线模式使用已归档事件，界面必须标出“缓存演示结果”。

### 10.3 六分钟演示顺序

```text
0:00-0:40  说明真实问题：教学视频难以结构化，新人操作难以规模化反馈
0:40-1:40  导入标准视频，一键生成 SOP，展示可编辑步骤
1:40-2:10  发布 SOP，切到学员角色
2:10-3:20  提交完整操作视频，展示分析进度与报告
3:20-4:20  点击步骤证据，解释分数由规则引擎产生
4:20-5:10  切换错误样本，对比漏步/错工具结果
5:10-5:40  展示视角不足时无法判断
5:40-6:00  总结创新：视频编译 SOP、跨视角语义事件、证据化评分、可信拒判
```

## 11. 数据与效果验证

### 11.1 当前主数据

- IMPACT：用于齿轮箱拆装/装配演示和视角差异测试。

### 11.2 本轮不以“训练准确率”为目标

本轮首先验证产品闭环，禁止把 fixture 指标当成模型准确率。至少输出：

- 每个样本识别到的步骤数量。
- 证据覆盖率。
- 正确步骤、错误步骤和无法判断步骤。
- 视频分析总耗时。
- Qwen 调用批次数。
- 不同视角的结果差异。

### 11.3 小规模功能验证集

建立最少 12 个固定样本：

- 正确流程 3 个。
- 漏步骤 2 个。
- 错顺序 2 个。
- 错工具或错对象 2 个。
- 遮挡/视角不足 2 个。
- 与 SOP 完全无关的视频 1 个。

样本不足时可以先使用已知官方标签和安全合成视频；报告注明这是功能验证集，不宣称生产准确率。

- 去掉不能点击或没有数据来源的装饰指标。

### 知识库

- 上传后立即显示处理状态。
- 视频可预览，手册可查看解析文本摘要。
- 提供“用此视频生成 SOP”快捷操作。

### SOP 编译室

- 左侧资产选择，中间步骤编辑器，右侧视频/证据预览。
- 编译进度不使用阻塞弹窗。

### 考评中心

- 改为选择 SOP、提交视频、查看进度、进入报告的顺序式页面。
- 会话历史放到次要区域，不让用户先理解内部 session 概念。

### 报告页

- EvidencePlayer 是第一视觉中心。
- 分数和六维度用于总结，不应压过实际步骤证据。

### 实时训练

- 大画面、当前步骤、画面质量和最近识别事件为核心。
- 结束训练后自动进入预录分析。

### 数据与模型

- 简化为“当前使用模式、模型是否可用、最近一次测试结果”。
- 暂时隐藏复杂审计、哈希和供应链信息。

## 14. 测试计划

### 14.1 后端单元测试

- 全局帧时间戳严格递增。
- 两遍采样不超过最大帧数。
- Qwen 批量 JSON 部分损坏仍可保留有效结果。
- 相邻事件合并和短时漏检容忍。
- 未知工序不回退错误词表。
- 关键步骤证据不足返回 inconclusive。
- 覆盖率 79%/80% 边界。
- 明确错工具、错序和漏关键步骤。
- job 进度、失败、重试和刷新恢复。
- 预览端点返回可播放内容并清理临时文件。

### 14.2 前端单测

- SOP 步骤增删、排序和权重归一。
- 考评进度状态转换。
- inconclusive 不显示为通过。
- 报告步骤点击生成正确 seek 时间。
- 在线/缓存演示状态标签。

### 14.3 Playwright 主流程

至少实现以下用例：

1. 教师登录 -> 上传标准视频 -> 生成 SOP 草稿。
2. 编辑 SOP -> 发布 -> 考评中心可选择。
3. 学员选择 SOP -> 上传视频 -> 自动完成考评 -> 打开报告。
4. 点击失败步骤 -> 视频跳转到证据时间。
5. 证据不足样本 -> 显示无法判断。
6. 实时训练开始/停止 -> 转入预录分析。
7. 管理员创建和停用账号。

CI 使用 Replay/Mock Provider，不消耗外部 API。另提供一个手动命令测试真实 Qwen。

### 14.4 UI 尺寸

- 390x844 手机。
- 768x1024 平板。
- 1440x900 桌面。

主要操作目标不小于 44px；无横向溢出；报告表格在手机上改为步骤列表，不强行压缩成宽表。

## 17. 主体功能完成标准

只有以下条件全部满足，才能宣布主体功能完善：

- 教师可以完全通过网页把标准视频变成可编辑并发布的 SOP。
- 学员可以完全通过网页提交视频并自动获得报告。
- 任务处理有真实进度、失败提示、重试和刷新恢复。
- 每个步骤结果能跳转到正确的视频时间证据。
- 错误操作样本与正确样本产生合理不同的结果。
- 关键证据不足时显示无法判断，而不是通过。
- 三类预置演示可一键运行，缓存模式断网也能展示完整结果。
- 实时页面不阻塞服务，并明确只是训练辅助。
- 后端、前端单测、类型检查、构建和七条 Playwright 主流程全部通过。
- 文档明确说明当前结果是比赛演示级功能验证，不是生产级技能认证。

## 18. 本轮最重要的取舍

不要同时追求“大模型实时识别、自研模型训练、跨平台打包、合规审计和更多 UI 页面”。本轮只把两个核心价值做强：

1. **一段教学视频可以快速变成结构化、可编辑、可考评的 SOP。**
2. **一段新人操作视频可以得到步骤级、可回放、有证据的反馈。**

这两条主线完整以后，再进入模型训练、准确率提升、Windows 打包、审计和参赛材料阶段。
