# 五分钟线下演示脚本

## 0:00–0:35 问题与方案

“传统技能教学的视频能看，但教师很难知道学生卡在哪一步。工序智传把完整示范视频变成可以逐步练习、逐步反馈的课程。”展示首页的教师与学生双角色闭环。

## 0:35–1:40 教师发布课程

用教师账号进入“教学素材”，展示已授权视频；进入“SOP 课程编排”，展示系统拆出的步骤、时间片段、完成条件与纠错提示。修改课程名称或学习目标并保存，说明教师审核后才能发布，模型不能自行决定教学标准。

## 1:40–3:05 学生实时陪练

切换学生账号，打开“课程与 AI 陪练”。展示当前步骤示范、标准完成图和摄像头区域。完成普通步骤后保持结果清晰约 1 秒，系统一次上传三帧；通过后自动进入下一步。展示错误提示或看不清补拍逻辑。说明普通步骤目标 5–6 秒，关键步骤两轮确认目标 8–12 秒。

## 3:05–3:45 学生学习报告

完成后展示本次练习指数、完成率、每步耗时、纠错次数与建议复习项。强调这些是过程记录，不是未经验证的“掌握度”或教学效果。

## 3:45–4:30 教师学情看板

切回教师账号打开“班级学情”，展示参与人数、完成率、核验调用量、共性薄弱步骤，再点击一条练习下钻。说明教师可以据此调整示范、条件或安排针对性复练。

## 4:30–5:00 可靠性与边界

展示三案例技术验证矩阵和 Provider 能力探测。说明断网时只打开明确标注的工程回放，不把回放冒充实时识别。结尾：“我们的创新不是只做视频理解，而是把教师标准、学生动作与可解释反馈连接成一个教学闭环。”

## 赛前检查

1. 运行 `Prepare-Contest.ps1 -Reset` 后启动，确认三个账号能登录。
2. 教师端执行 Provider 能力探测，确认图像输入通过。
3. 检查摄像头权限、光线、背景和目标物完整入镜。
4. 保留学生预置完成记录作为工程回放；口头明确它不是实时结果。
5. 不展示 `.env`、API Key、学校或指导教师信息。
