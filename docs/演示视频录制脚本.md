# 工序智传演示视频录制脚本

> 本脚本已归档。2026-10-15 最终线下演示请使用 `CONTEST_DEMO_SCRIPT_5MIN.md`，不要使用本文中的旧公网地址或不存在的二维码。

## 成片要求

- 建议成片时长：2 分 40 秒至 2 分 50 秒。
- 分辨率：1920×1080，30fps。
- 导出：MP4 / H.264，视频码率 4–6Mbps，AAC 音频 128kbps。
- 预计大小：90–140MB，满足不超过 200MB 的要求。

## 录制前准备

- 准备一个已发布 SOP、一段标准教学视频、一段新人操作视频，以及一条已完成的真实考评记录。
- 浏览器缩放设为 100%，关闭无关标签页、通知和终端窗口。
- 实际 Qwen 分析需要数分钟。录制时先展示任务已提交和开始分析，再等待同一任务完成后录制报告页；剪辑时添加“实际分析过程已加速展示”字幕。
- 主演示使用真实完成记录。`fixture_replay` 仅可作为补充，不作为真实模型结果展示。

## 分镜与旁白

| 时间 | 页面与操作 | 旁白 |
|---|---|---|
| 0:00–0:10 | 登录后进入“工作台”，展示已发布 SOP、最近考评记录。 | 工厂里大量有价值的操作经验，往往只存在于老师傅的教学视频里。新人学习靠反复观看，管理者也难以客观判断操作是否规范。 |
| 0:10–0:25 | 点击“知识导入”，展示标准教学视频、手册资产、加密存储状态。 | 工序智传把标准教学视频、设备手册和安全规范统一导入。原始文件本地加密保存，只有获得明确授权后，系统才会将压缩关键帧交给外部 AI 分析。 |
| 0:25–0:50 | 进入“SOP 编译室”，选中已有标准视频与关联手册，展示 SOP 步骤、动作、对象、顺序和发布状态。 | 系统不是只给出一段文字总结，而是把视频和手册编译为可校对的 SOP：每一步做什么、使用什么对象、先后顺序如何，都可以由教师审核后发布。 |
| 0:50–1:05 | 放大 SOP 中 2–3 个步骤和受控词表。 | 这一步把隐性的经验变成结构化、可追溯、可复用的教学标准。后续的考评，不再依赖模糊的印象分。 |
| 1:05–1:25 | 进入“预录考评中心”，选择已发布 SOP，选择新人操作视频；勾选“允许外部 AI 分析关键帧并生成教学反馈”。 | 新人只需要提交一段完整操作视频。系统会先确认考评所依据的 SOP，再要求上传者明确授权关键帧分析。没有授权，系统会拒绝外发，而不是静默调用模型。 |
| 1:25–1:35 | 点击“提交并开始分析”，录到任务进入排队或分析进度。 | 任务提交后，后台自动抽取关键帧、对齐 SOP，并进行步骤级判断。这里展示的是同一条真实任务的启动状态。 |
| 1:35–1:38 | 剪辑转场，屏幕显示“实际分析过程已加速展示，以下为同一任务的真实报告”。 | 分析完成后，系统自动打开报告。 |
| 1:38–2:10 | 回到同一条完成记录，展示最终结果、分数、证据覆盖率、分析用时；点击证据播放器中的一个步骤。 | 报告不会只给一个总分。每个步骤都有通过、未通过或证据不足的判断，并可回看对应的视频证据。系统把哪里做错了、为什么判断、应如何复练说清楚。 |
| 2:10–2:28 | 展示一个未通过或证据不足步骤，再展示右侧六维得分与教学反馈。 | 对于关键步骤，系统会给出可观察依据和复练建议。固定规则负责评分，大模型负责解释已有判断，不直接修改分数，避免黑箱打分。 |
| 2:28–2:40 | 进入“数据与模型”，短暂展示 Qwen 已配置、公开数据边界；可快速切至“账号设置”显示角色。 | 平台支持管理员、教师、学员和观察者角色。公开数据只用于开发验证；系统不会把开发集结果包装成工业级准确率。 |
| 2:40–2:50 | 回到工作台或项目 Logo，最后展示二维码。 | 工序智传，让老师傅的经验从一段视频，变成可传承的 SOP、可解释的考评和可持续改进的教学闭环。 |
