## 已完成的主体流程

### 1. 教师知识与 SOP 流程

1. 教师上传有来源说明的视频或手册。
2. 资产加密入库，后台任务完成视频处理或文档切片。
3. 只有已完成索引的手册才能进入 RAG 与 SOP 编译。
4. 标准视频按真实时间戳抽帧，由外部多模态 Provider 生成受控结构化候选。
5. 后端绑定视频和手册来源，执行 Schema、DAG、权重、证据类型和来源等级校验。
6. 教师在编辑器修改步骤、工具、对象、动作、前置关系、关键性、时长和权重。
7. 草稿通过校验后发布；学员侧只显示已发布版本。

正常 `/sops/compile` 与后台编译任务均拒绝使用固定 ReplayProvider。Replay 只用于显式健康探测或答辩 fixture，不会进入普通教师业务链。

### 2. 学员预录考评流程

1. 学员选择已发布 SOP，并在同一向导内上传视频。
2. 系统完成资产登记、加密、会话创建和 `recorded_assessment` 任务入队。
3. 页面按 job/session 恢复进度，显示阶段、已分析帧数、预计剩余时间和失败原因。
4. 第一遍全片均匀采样最多 24 帧；在步骤或语义变化处进行第二遍自适应补帧，总数不超过 48。
5. Qwen 视觉适配器按受控词表输出工具、对象、动作、阶段、候选步骤和可见依据；本地确定性代码负责过滤、时序合并和评分。
6. 后端合并时间事件，严格校验 SOP 声明的工具、对象和动作，再进行步骤对齐。
7. 固定评分引擎生成结果、六维分数、覆盖率、步骤判定、规则码和证据时间线。
8. 完成后页面自动打开报告；失败步骤可跳转到对应证据。

每条视觉检查独立保存为 `passed`、`failed` 或 `insufficient_evidence`。
`completion_checks` 用于工件最终状态，`observable_checks` 只用于独立的可观察安全
规范；工具、对象和动作匹配只证明步骤语义，不能自动推导完成正确、防护或断电已经
通过。关键安全检查缺证据时结果保持无法判断；完成状态缺证据保留为提示，不再单独否决动作证据充分的高分操作。当前评分契约为 `scoring-v6`，旧版报告
不能命中新版结果缓存。

候选步骤只用于路由，不提供通过加分；低置信 `hand_present`、缺少动作关系或缺少 SOP 声明字段均不能单独判步骤通过。明确看到不兼容工具、对象或动作才判失败；没看清时返回证据不足。

### 3. 后台任务与恢复

- worker 支持 `asset_process`、`sop_compile` 和 `recorded_assessment`。
- 任务具有阶段检查点、可见进度、心跳租约、自动重试和手动重试。
- worker 异常退出后，过期租约可被重新领取。
- API 与 worker 启动时只清理严格白名单内的遗留临时明文目录，不触碰资产、数据库、模型和日志。

### 4. 自动报告与人工报告分离

- 正式自动报告必须由对应 `recorded_assessment` worker 任务在同一事务中绑定来源。
- 人工提交统一标记为 `manual_review`，不能冒充模型版本。
- 自动恢复只接受与当前 job 精确绑定的报告，不接受会话中任意已有报告。
- 缓存只复用同一上传者、视频 SHA256、SOP 版本、视觉模型版本、评分规则版本和成功自动任务的结果。
- fixture、Replay、人工报告、无模型和未调用 Provider 的拒判结果均不能进入正式结果缓存。
