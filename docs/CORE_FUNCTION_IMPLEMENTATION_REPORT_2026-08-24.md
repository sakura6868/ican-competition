## 1. 实施结论

本轮已将项目从分散的功能原型推进为一套可操作的主体产品：教师能够导入标准视频和手册、生成并编辑 SOP、发布不可变版本；学员能够选择已发布 SOP、上传操作视频、等待后台分析并查看步骤级证据报告；摄像头训练结束后能够把浏览器内存录像转入正式预录考评；管理员能够管理账号；答辩时可以加载三类稳定工程回放。

工程流程已经闭合，但模型效果证据尚未闭合。当前可以演示“系统怎样工作、怎样拒绝无证据判断、怎样给每个扣分项绑定证据”，不能宣称“已在真人目标工序上达到某准确率”或“已可用于工业认证”。

当前成熟度判断：

- 主体后端与前端：`implemented/integrated`
- 外部视觉语义链：配置真实 Provider 后可运行，尚未独立验证
- 本地视觉链：具备通用辅助事实，尚不具备目标工序专用识别能力
- 模型准确率：`unvalidated`
- Windows 开发启停脚本：已实现，待真实 Windows 11 验收
- Windows 便携成品与最终发布：暂缓

## 3. 最终产品流程

```text
教师端
授权标准视频/手册
  -> 加密上传
  -> 后台处理与手册索引
  -> 多模态关键帧分析 + 限定资产 RAG
  -> SOP 草稿
  -> 教师编辑与校验
  -> 发布不可变版本

学员端
选择已发布 SOP
  -> 上传本人操作视频
  -> 创建考评会话和后台任务
  -> 全片采样与视觉事实
  -> 时间事件合并
  -> SOP 步骤对齐
  -> 固定规则评分
  -> 步骤证据报告

实时训练
摄像头即时辅助
  -> 浏览器内存录像
  -> 结束训练
  -> 提交到上述预录考评
  -> 正式报告
```

## 4. 关键实现成果

### 4.1 资产和知识链

- 上传文件计算 SHA256，并以 AES-256-GCM 保存加密资产。
- 明文仅存在于受限临时工作区；正常请求结束、API 启动和 worker 启动均有清理路径。
- 视频处理和文档解析由后台任务执行，页面可见真实状态。
- 手册解析为加密文档切片；RAG 只检索本次明确选择的资产，避免跨资料串用。
- SOP 编译只接受已经建立索引的手册，未处理资料会明确拒绝。
- 每个资产记录来源说明和是否允许必要内容外发。

### 4.2 标准视频到 SOP

- `sop_compile` 后台任务提供探测、采样、视觉分析、编译和草稿完成等阶段进度。
- 外部多模态 Provider 最多按 4 帧一批分析，标准视频可覆盖最多 24 个全片时间点，而非只分析开头若干秒。
- Provider 输出经过结构化适配，系统字段、步骤编号和来源绑定由后端控制。
- SOP 校验覆盖连续编号、DAG、权重、工具/对象/动作、可观察检查、证据类型和来源等级。
- `video_reference` 必须有视频来源；`manual_backed` 必须绑定手册；来源资产类型与引用类型必须一致。
- 正常同步和异步编译均拒绝固定 ReplayProvider，避免把预置角磨机 SOP 写入真实教师流程。
- 编辑器支持步骤新增、复制、删除、排序、字段编辑、前置关系和权重归一；发布后再编辑会形成新草稿。

### 4.3 预录视觉分析

- 第一遍从完整视频均匀抽取最多 24 帧并保留真实时间戳。
- 第二遍根据候选步骤、阶段和语义变化在转换点附近补帧，总数硬限制为 48。
- 第二遍失败时保留第一遍结果；外部 Provider 瞬时失败进入任务重试，不固化为伪成功报告。
- Qwen 输出受当前 SOP 动态工具、对象和动作词表约束，并包含候选步骤、阶段、置信度和可见理由。
- 单个错误 JSON 项不会丢弃整批有效事件；批请求失败可逐帧降级；单任务有调用上限。
- Qwen 的视觉 prompt/parser contract 和 ONNX 两份权重内容进入版本标识，避免旧视觉缓存跨契约复用。

### 4.4 事实、对齐与可信拒判

- 相邻检测合并为有起止时间的观察事件，允许短时漏检。
- 短单帧证据必须同时具备高置信动作和工具/对象关系；仅有人手或候选步骤不足以通过。
- SOP 声明了工具、对象或动作时，每个声明维度都需要真实匹配。
- 明确看到不兼容字段时可返回 `wrong_tool`、`wrong_object` 或 `wrong_action`。
- 遮挡、低置信、缺字段或质量不足返回 `insufficient_evidence`，不冒充操作错误。
- optional 步骤不进入必做覆盖率、关键缺失和强制计分。

### 4.5 确定性评分

- 多模态模型只提供事实候选，不直接写数值分数。
- 本地规则引擎统一计算完整性、顺序、工具零件、动作质量、效率和可观察安全。
- 关键步骤明确失败时执行失败规则；关键步骤证据不足或整体覆盖率不足时结果为 `inconclusive`。
- 没有证据时各维度和总分为 0，不再出现“无证据效率满分”。
- 报告保存模型版本、评分规则版本、输入哈希、步骤规则码和证据范围。
- 可观察检查逐项保存三态事实；普通步骤语义通过不再自动推断安全检查通过。
- 混合检查状态按逐项等权计算，关键项缺证据保持 `inconclusive`，明确关键违规保持 `fail`。
- 评分规则升级为 `scoring-v3`，避免旧版粗粒度安全分被缓存复用。

### 4.6 正式报告、人工报告与缓存

- 人工评分入口忽略客户端伪造的模型版本，统一保存为 `manual_review`。
- 正式自动报告由 worker 与具体 `recorded_assessment` job 事务绑定。
- 崩溃恢复只接受该 job 自己绑定的报告，人工报告不能使自动任务错误地提前完成。
- 自动缓存同时校验上传者、视频 SHA256、SOP 版本、模型版本、评分规则版本和成功任务来源。
- fixture、Replay、人工报告、无模型和未调用 Provider 的记录不进入正式缓存。
- 命中缓存时复制步骤判定、观察事实和报告到新会话，并保存来源会话，避免跨用户证据泄露。

### 4.7 证据报告

- 报告展示通过、未通过或无法判断，不用临时分数伪装绿色通过。
- 步骤列表包含实际识别到的工具、对象、动作、置信度、判断理由和时间范围。
- 证据图端点按步骤保存的 `keyframe_ref` 查找同一观察的精确时间戳，不再用步骤区间中点替代证据。
- 视频和证据图均要求登录并执行会话归属校验，临时解密/抽帧目录在响应结束后清理。
- 前端 `EvidencePlayer` 支持点击步骤跳转、时间线联动和失败证据聚焦。

### 4.8 实时训练与正式考评衔接

- 摄像头预览、WebSocket 状态和低频语义提示属于训练辅助。
- 外部画面分析需要显式授权；未授权不会静默出站。
- 结束时使用 `MediaRecorder` 生成浏览器内存录像并调用正式 `submit-video` 流程。
- 页面获得 session ID 后轮询同一正式任务，并提供报告链接。
- 实时摘要与正式报告在产品文案和数据路径上分开，避免把临时反馈当考试成绩。

### 4.9 答辩工程回放

- 工作台提供完整操作、明确错误和视角不足三类入口。
- fixture 只提供冻结的视觉事件，后续事件合并、步骤对齐和评分复用正式代码。
- 页面显示 `fixture_replay` 和免责声明。
- 工程回放用于无网络时稳定展示交互与规则，不写入正常模型缓存，也不作为准确率数据。

## 6. 模型和数据真实性说明

### 6.1 当前真正使用的能力

- 外部 Qwen 类多模态 API：负责关键帧中的工具、对象、动作和候选步骤语义。
- MediaPipe HandLandmarker：负责本地手部存在与基础位置事实。
- YOLOv8n COCO ONNX：负责人物和少量通用对象辅助事实。
- 本地时间事件、步骤对齐和评分规则：负责最终判断与数值。

### 6.2 当前没有完成的能力

- 没有训练目标工序专用工具、零件或动作模型。
- 没有通过视频判断真实扭矩、电压、压力或内部装配状态。
- 没有目标工序固定真人测试集上的步骤精确率、召回率、F1、拒判率或跨视角泛化指标。
- 没有证明通用 YOLO 可以替代工序专用检测器。

### 6.3 Fixture 与模型准确率

仓库中的 `training-metrics.json` 来源于三个确定性 fixture 场景。它可以验证：

- 事件能否进入对齐器；
- 漏步骤和错工具规则是否触发；
- 相同输入是否得到相同分数；
- 报告能否绑定步骤证据。

它不能验证：

- 模型是否能从真人视频正确识别这些事件；
- 新人物、新视角、新光照或遮挡下的泛化；
- 工业现场的安全合格率。

因此所有 fixture 数字继续标记为 `experimental_unvalidated`，不得出现在答辩“模型准确率”结论中。

## 8. 当前能否完成全部流程

### 可以完成

- 在真实 Provider、后端 worker 和必要授权配置正确时，代码具备教师视频到 SOP、学员视频到报告的完整路径。
- 在不依赖网络时，三类 fixture 可以稳定完成答辩工程回放。
- 证据不足、没有模型、未授权外发和瞬时 Provider 故障均有明确状态，不需要伪造成功。

### 尚不能保证

- 任意教学视频都能生成可直接发布的高质量 SOP；教师仍需校对。
- 任意视角的真人操作视频都能正确识别所有步骤。
- 目标工序达到某个准确率、召回率或工业安全标准。
- Windows 统一开发脚本已能启动 API、worker 和前端，但真实 Windows 11 的完整摄像头、FFmpeg、ONNX 与冷启动仍未验收。

所以当前结论是“主体流程工程上完整，真实效果与发布交付仍需验证”，不是“功能一切完善”。

## 9. 下一步主体完善计划

### P0：冻结参赛演示工序

1. 选择一个 5 至 8 步、桌面完成、无危险操作、工具和状态变化明显的工序。
2. 冻结工件、工具、SOP v1、主机位、备用机位、光照和背景。
3. 准备一条授权标准教学视频和对应设备手册。
4. 明确可见检查与不可见检查；不可见参数不得让视频模型打分。

完成标准：教师能够从真实标准视频生成草稿，经少量校对后发布；所有证据引用可跳转到正确时间。

### P0：建立固定真人验证集

1. 录制完整操作、漏关键步、错工具/对象/动作、错序、遮挡和视角不足视频。
2. 视频由授权成年人执行安全动作，不把危险动作交给老人或未培训人员。
3. 为每段视频记录人物、视角、步骤起止、错误类型和可判断性真值。
4. 按人物和视角隔离训练/验证/测试，冻结测试集后不得用于调 prompt、词表或阈值。
5. 对争议样本进行人工复核；真值不能由待测模型自动生成并自我证明。

完成标准：数据清单、人工真值和冻结划分可复现，且所有视频有合法授权。

### P1：真实 Provider 效果验证

1. 在训练/验证集上调整关键帧策略、受控词表和 prompt contract。
2. 记录每段视频的步骤判定、证据、拒判原因、调用次数、延迟、费用和重试次数。
3. 分别统计步骤级精确率、召回率、F1、明确错误识别率、可信拒判率和误报情况。
4. 固定所有配置后只运行一次冻结测试集，并归档逐样本失败案例。
5. 未达标时如实缩小可识别步骤范围，不修改测试真值或删除失败场景。

完成标准：模型卡中的指标来自固定真人测试集，而不是 fixture。

### P1：全栈与答辩排练

1. 在已有本地真实栈 smoke 基础上，配置授权 Provider，跑通真实标准视频生成 SOP 与学员视频自动判定。
2. 用物理摄像头验证实时训练结束后确实创建正式预录任务。
3. 在桌面、平板和手机尺寸检查遮挡、横向溢出、触控尺寸、控制台错误和 PWA 状态。
4. 准备在线真实分析、离线 fixture 和预先归档真实报告三种演示备份。
5. 统一答辩口径：工程回放、真实 API 结果和人工报告必须明显区分。

完成标准：六分钟演示可重复，断网或 Provider 失败时能可信降级而不中断讲述。

### P2：阶段 12（继续暂缓）

主体效果验证完成后再处理：

- 在 Windows 11 真机验收现有 API、worker、前端统一启停脚本，以及摄像头、FFmpeg 和 ONNX。
- 在上述验收通过后制作内置依赖的 Windows 便携成品。
- Docker/便携包、版本锁定、SBOM、许可汇总和发布清单。
- 发布包 SHA256、断网新目录冒烟和最终比赛材料。

## 10. 人工边界

## 11. 最终评价

本轮已经解决了“页面能点但主体闭环不连贯”的主要问题，也补上了证据语义、任务恢复、缓存污染、人工/自动报告混淆、Replay 进入正常业务、低证据高分和临时明文恢复清理等关键风险。接下来最有价值的工作不再是继续堆页面或发布脚本，而是冻结一个真实工序、建立可靠真值、跑真实 Provider 并形成可审查的效果证据。只有这一步完成，项目才从“比赛级工程原型”进入“有真实效果依据的参赛作品”。
