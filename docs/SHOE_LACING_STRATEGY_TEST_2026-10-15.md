# 普通教学步骤多帧核验实测（鞋带穿法）

测试日期：2026-10-15

本次用一个与折纸不同的普通教学案例，验证以下陪练策略：

- 普通步骤：一次提交 3 帧、跨度至少 1 秒；模型确认完成后立即进入下一步。
- 关键或安全步骤：连续两次独立核验通过后再进入下一步。
- 画面不清：返回“无法判断”，保持当前步骤，由网页端自动采集新画面再次核验。
- 明确错误：保持当前步骤，并使用该完成条件对应的纠正提示。

## 测试素材

- 课程：鞋带平行横条穿法
- 原视频：`Shoe Lacing Methods`，Lrcolette
- 来源：[Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Shoe_Lacing_Methods.webm)
- 许可：[CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/)
- 本地文件：`samples/public-videos/shoe-lacing/shoe-lacing.webm`
- 视频参数：64.9 秒，960×540，29.97 fps，VP8
- SHA-256：`ffd0f7884632356388d32adad0e8a471f95608b87cfda77d1d9969455368735d`

系统对完整视频进行 18 帧抽样和 3 个时间窗分析，API 编译耗时 59.21 秒。模型先生成 3 个较粗步骤，教师端随后将课程校对为 4 个可观察步骤并发布：

1. 穿好鞋面下部横条。
2. 继续穿好鞋面中部横条。
3. 穿到顶部鞋眼。
4. 整理两端并展示成品。

教师校对时还发现模型最初把视频中的平行横条误写成可见 X 形，并加入“两端长度接近”这一视频没有充分证明的条件。发布版已删除这些错误条件。这个结果说明，通用场景应保留教师审核，模型生成的 SOP 草稿不能直接发布。

## 普通步骤实时核验结果

每次请求包含 3 张不同图像数据，采集时间跨度至少 1 秒。完成状态测试采用同一公开视频的帧回放，并对最终状态做轻微编码变化，模拟学员将完成结果稳定保持在镜头中。

| 测试 | API 判定 | 状态变化 | API 耗时 |
|---|---|---|---:|
| 全黑、无法观察 | `unknown` | 停留在第 1 步，提示调整视角 | 3.04 秒 |
| 第 1 步完成 | `satisfied` | 第 1 步 → 第 2 步 | 3.31 秒 |
| 第 2 步完成 | `satisfied` | 第 2 步 → 第 3 步 | 3.21 秒 |
| 第 3 步完成 | `satisfied` | 第 3 步 → 第 4 步 | 3.33 秒 |
| 第 4 步完成 | `satisfied` | 课程完成 | 3.32 秒 |

4 次普通步骤完成核验全部一次通过，API 平均耗时 **3.29 秒**，范围 **3.21～3.33 秒**。网页端在调用前需要先积累约 2～2.5 秒的时间序列画面，所以用户从开始展示完成状态到首次跳步的总体等待约为 **5～6 秒**。

黑屏测试返回 `unknown`，没有计为错误，也没有跳步。网页端定时器会继续采集新帧并再次提交，因此学员只需调整视角，无需手动点击“重试”。

## 明确错误与纠正提示

在校对过程的审计测试中，系统对一个稳定可见、与完成条件相反的状态返回：

- 判定：`violated`
- API 耗时：4.28 秒
- 状态：停留在当前步骤并进入 `correcting`
- 原因：“鞋带左右两端长度差异极大，左端过长右端过短，未拉齐，不满足长度大致接近的要求。”
- 提示：“拉动较短的一端使两端长度接近，再把鞋面上翻折或扭转的鞋带逐层理平。”

这条条件后来因缺少标准视频证据而从最终 SOP 删除，但该次测试确认了 `violated → 当前条件的 correction → 保持当前步骤` 的状态机路径可以工作。另一次审计还正确识别了教师误写的 X 形条件与视频成品不一致，从而暴露出教师条件本身有误。

## 关键与安全步骤

后端会把 `critical=true` 或必需的安全检查自动设为 `confirm_windows=2`。两次核验必须来自后续独立请求，且都满足多帧证据要求，才允许跳步；任意一次不确定或违反条件都会清空累计确认。

这一分支已由状态机单元测试覆盖。本次鞋带课程的 4 步均为普通步骤，因此没有再次用真实 API 测量关键步骤。按两次 API 调用和采集间隔估算，关键或安全步骤约为 **8～12 秒**。

## 结论与边界

此次回归证明策略已经落入产品代码，并在另一类普通教学视频上完成端到端 API 验证：普通步骤一次多帧核验后跳步，不清楚时自动补拍，明确错误时给出条件对应的修正提示，关键/安全步骤保留双重确认。

这仍是工程功能验证，不是识别准确率评测。完成步骤使用的是标准教学视频回放，且多个步骤复用了最终成品画面；尚未覆盖真实摄像头、独立学员、遮挡、不同背景和真正的错误动作样本。下一阶段应为每门候选课程采集多人正误样本，建立逐条件混淆矩阵与平均跳步时延。
