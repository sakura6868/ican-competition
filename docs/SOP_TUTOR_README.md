# SOP 视频教学与实时陪练：第一版使用说明

更新：2026-10-13。已实现视频备课、教师校对、逐条件核验、练习状态机和陪练页面。
已接入 TokenRhythm 的 `qwen3.8-max`，通过真实 API 的多图、视频备课与合成陪练样本验证。
真实器材、完整操作视频与学员样本的识别准确率仍需实测。

2026-10-15 更新电脑端教育界面，页面入口与开源复用说明见 [教育界面说明](EDUCATION_UI_README.md)。

## 启动

在项目根目录打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-tutor.ps1
```

需要 Python 3.12、uv、Node.js/npm。脚本会安装后端和前端依赖、迁移数据库，
首次生成 `.env` 并交互创建管理员。密码不会显示；已有管理员和配置会保留。
已有开发加密密钥会被沿用，避免原视频无法解密。

页面地址为 `http://127.0.0.1:5185`，API 地址为 `http://127.0.0.1:8011`。
启动窗口保持打开，Ctrl+C 停止本次服务；日志在 `.runtime/tutor/`。
依赖已安装后，可以加 `-SkipInstall`。

本机项目根的 `.env` 已保存用户提供的接口配置。重新部署时按以下格式配置：

```dotenv
GONGXU_LLM_MODE=live
GONGXU_LLM_BASE_URL=你的视觉模型兼容接口地址，包含 /v1
GONGXU_LLM_API_KEY=你的 API Key
GONGXU_LLM_MODEL=你已开通的视觉模型名称
GONGXU_VISION_BACKEND=qwen
```

当前接入复用了原项目的 Qwen/OpenAI 兼容多图接口，包括 Qwen 的
`enable_thinking` 配置。更换供应商时应核对其参数兼容性。
百炼地址、地域和可用模型以[官方视觉文档](https://help.aliyun.com/zh/model-studio/vision)为准。
修改配置后重启服务。密钥只填本地文件；前端获取的配置状态只有布尔值。

本机已验证的配置为：Base URL `https://tokenrhythm.studio/v1`，
聊天路径 `/chat/completions`，模型 `qwen3.8-max`。
真实密钥仅保存在本地 `.env`，Git 与源码打包均排除该文件。

没有模型配置也能启动和查看页面，视频自动编译与摄像头核验会明确提示缺少配置。
普通电脑负责采集与状态控制，模型推理在云端执行。
浏览器摄像头需在 localhost 或 HTTPS 下使用；远程演示应配置 HTTPS。

## 教师备课

1. 在“知识导入”上传清晰的 H.264 MP4 教学视频，填写授权说明并勾选允许 AI 分析。
2. 在“SOP 编译室”选择视频和工序标识，点击“生成 SOP 草稿”。
   新页面默认启用教学模式；API 调用时传 `teaching_mode: true`。
3. 校对全部步骤：原视频开始/结束时间、操作说明、前置关系、完成条件、纠错提示。
   确保本步结束前已展示清楚的完成状态。
4. 确认本工序的工具、对象和动作词表。每一步至少有一条必要的可视完成条件。
   摄像头无法判断的强度、扭矩或内部质量可设为“教师人工确认”。
5. 勾选每步“我已校对……”，保存草稿，再发布版本。
   修改片段、核验条件或操作说明后会撤销该步校对确认。

原有 SOP 也可通过“启用本步骤陪练”补充上述信息。
课程发布前会重新核对教师确认、来源视频和片段时长。
已发布课程的修改会生成新草稿，已开始的练习保留启动时的课程快照。

备课默认使用 30 秒窗口、3 秒重叠，每窗最多发送 6 张采样图。
窗口覆盖视频全部时长，模型综合所有窗口合并动作，再生成教学片段。
这属于覆盖全片的取样理解，快速动作和精确时间边界需要教师校对。
默认上限为 40 个窗口；超限会提示分成子课程或调整配置，防止尾部静默遗漏。

讲解音频可以通过开源 faster-whisper 在 CPU 上转写，并按时间对应到各窗口：

```powershell
cd backend
uv sync --extra media --extra teaching
```

然后在 `.env` 设置 `GONGXU_ASR_MODEL=small` 并重启。
首次使用需要下载模型权重；本次未下载或验证该模型。
留空表示采用视觉备课，界面不会把它宣称成已经理解了语音讲解。

## 学员练习

1. 进入“实时陪练”，选择教师已确认的课程，确认练习画面的分析授权。
2. 看当前步骤示范，将摄像头对准工作区，开启摄像头，按步骤操作。
3. 自动检查开启时，系统每 2.5 秒尝试提交近期新画面，同一练习只保留一轮待处理核验。
   检查按钮也走同一核验流程。
4. 完成全部必要条件后，连续 2～4 个新画面窗口确认通过，自动进入下一步。
   重复提交完全相同的图片无法累计完成确认。
5. 明确装错时显示对应条件、可见依据和教师的纠错提示；修正后重新核验。
   操作未结束会继续观察；遮挡或看不清会要求调整视角并留在当前步骤。
6. 可暂停继续、刷新恢复进度、跳过已标为可选的步骤，完成后查看步骤用时和纠错次数。

人工条件由教师账号打开同一个练习地址，填写核验依据后确认。
人工确认本身不会替代必要的视觉完成检查。第一场参赛演示建议优先使用纯视觉可核验的课程。

云端检查有请求超时、过期结果丢弃和失败恢复。5 秒一次的进度恢复轮询也会清理
已超时的待处理观察，避免 worker 中断后页面一直等待。实际反馈速度取决于模型和网络，
尚无实测延迟承诺。默认每次练习最多提交 300 轮检查，可在 `.env` 调整。

## 实现与开源参考

| 项目 | 参考内容 | 本项目的实现方式 |
| --- | --- | --- |
| [NVIDIA Live VLM WebUI](https://github.com/NVIDIA/live-vlm-webui) | 异步视频预览与模型分析、单轮在途调度 | Vue 采集近期画面，独立实时队列处理，SSE 推送反馈 |
| [NVIDIA SOP Monitoring Blueprints](https://github.com/NVIDIA/sop-monitoring-blueprints) | 将操作观察与 SOP 条件判断分开 | 云模型只输出逐条件观察，后端规则决定步骤推进 |
| [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | CPU 语音转写 | 可选备课依赖，转写文本按时间加入视频窗口 |

Live VLM WebUI 参考源码提交：`2fd5ba0b334c334d24bf0f9439d8742b243d22be`。
本实现借鉴其调度思路并适配当前 FastAPI/Vue 项目；NVIDIA GPU 微服务属于后续扩展路径。
这三个项目的出处也保留在原调研文档中。

主要代码：

- `backend/gongxu/sop/teaching.py`：全片窗口、时间轴、可选转写、教师确认门禁。
- `backend/gongxu/practice/verifier.py`：真实多图调用、逐条件 JSON 与证据校验。
- `backend/gongxu/practice/state_machine.py`：纠错、持续确认、前置条件与下一步。
- `backend/gongxu/practice/service.py`：授权、加密画面、幂等提交、并发控制和超时恢复。
- `backend/gongxu/practice_worker.py`：专用实时队列，避免被离线备课和考评作业阻塞。
- `backend/gongxu/api/routes/practice.py`：课程、会话、事件流、标准片段与证据帧接口。
- `frontend/src/views/PracticeView.vue`：摄像头、示范、条件状态、纠错与恢复。
- `frontend/src/views/SopStudioView.vue`：教师校对与发布。

数据库迁移新增练习会话、观察与事件三张表；核心 API 前缀为
`/api/v1/practice-sessions`。启动 API 默认内置实时 worker。
单独运行 `python -m gongxu.practice_worker` 时，将 API 的
`GONGXU_PRACTICE_WORKER_ENABLED` 设为 `false`。
原 `gongxu.worker` 继续负责视频处理、备课和离线考评。

学员图像和标准图缓存以现有 AES 加密机制保存，临时解密文件用完清理。
学员画面默认保留 7 天，过期清理保留事件元数据和核验结论。
审计收据保存输入摘要、模型名、token 用量和调用延迟；条件和标准图也绑定到输入摘要。

真实参赛验收还需要选定器材、录制标准视频，并采集完整/装错/遗漏/遮挡样本。
第一版建议固定机位和 5～6 步大零件桌面装配；识别效果以这些实测样本为准。
当前自动核验面向本步骤；已完成结构被后来拆除后的持续回查与回退尚待扩展。
教师应在最后安排可见的整体自检步骤。语音陪练、多学生并发调度和训练专用动作模型也属于后续范围。

原源码包缺失研究数据集模块 `gongxu.data`。本次补回主程序必需的
`sha256_file`，教学与陪练核心可运行；原数据集下载/评测脚本的完整恢复属于独立工作。
因此本次验证针对新功能及可运行的核心测试，没有把整套研究数据测试或原项目全部 CI 宣称为通过。
